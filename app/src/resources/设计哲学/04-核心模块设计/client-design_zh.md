# 客户端设计

AgentGo 客户端包括 Web 管理界面与桌面客户端。两者共享用户心智模型和后端契约：用户管理资源、选择或配置 Agent、提交任务，并持续查看执行过程与结果。

## 职责与边界

客户端负责输入采集、界面状态、任务进度呈现、资源管理操作入口，以及在用户明确授权后调用本地能力。权限判定、资源持久化、任务编排和工具执行的最终裁决均由后端及运行时承担。

| 能力       | 客户端职责                                 | 协作边界                                 |
| ---------- | ------------------------------------------ | ---------------------------------------- |
| 身份与会话 | 发起登录、保存短期界面状态、展示会话状态   | 不自行授予权限或长期保存敏感凭据         |
| 多模态输入 | 校验大小与类型、上传文本、图像、文件或音频 | 由服务端确认接收与可用性                 |
| 资源管理   | 提供创建、查看、更新、删除和授权的交互     | 以 Management API 返回的结果为准         |
| 任务体验   | 提交任务、流式展示状态、支持取消与重试     | 状态来自 AgentGo SA 的权威事件或查询结果 |
| 本地能力   | 桌面端在明确许可下桥接文件、通知等能力     | 最小权限、可撤销且可审计                 |

## 交互原则

1. **可见的执行边界**：任务开始前说明将使用的 Agent、资源和需要的确认；执行时展示阶段、工具调用摘要与失败原因。
2. **渐进式授权**：只在实际需要本地文件、系统能力或外部服务时请求授权；拒绝后保留可理解的替代路径。
3. **一致性**：Web 与桌面端使用相同的领域术语、资源状态和错误语义，避免客户端自行解释服务端状态。
4. **韧性**：网络中断时保留草稿和最近可安全缓存的界面状态；恢复连接后重新查询任务权威状态，避免重复提交。

## 状态与错误处理

客户端将任务区分为“等待提交、已接受、运行中、等待确认、完成、失败、已取消”等面向用户的状态。实际状态名称及事件字段必须以已发布契约为准。对于权限不足、资源不可用、网络问题和运行时错误，应提供不同的恢复建议，且不得暴露凭据、内部堆栈或其他用户数据。

## 可访问性与安全

所有关键操作必须可键盘访问，有可感知的焦点和状态反馈。敏感信息默认遮蔽；客户端日志不得记录令牌、密钥或完整私密内容。桌面端的本地桥接必须使用显式的允许列表，而不是向渲染层暴露通用系统执行能力。
