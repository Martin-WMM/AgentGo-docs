# 核心模块设计

本目录说明 AgentGo 的核心模块如何以清晰的职责边界协作。具体的 API 字段和数据模型以已发布的后端契约为准；尚未发布的能力在本文档中仅作为设计约束说明。

| 模块                                               | 主要职责                                    | 不负责的事项             |
| -------------------------------------------------- | ------------------------------------------- | ------------------------ |
| [客户端设计](./client-design_zh.md)                | 提供 Web 与桌面交互、会话呈现和本地能力接入 | 服务端业务规则与权限裁决 |
| [资源管理模块设计](./resource-management_zh.md)    | 管理用户环境资源、授权引用与可运行配置      | 直接执行模型决策         |
| [AgentGo SA 设计](./agentgo-sa-design_zh.md)       | 编排一次 Agent 任务的状态、节点与反馈闭环   | 持久化资源的权威管理     |
| [Agent Runtime 设计](./agent-runtime-design_zh.md) | 在受控边界内调用已授权工具与服务            | 决定任务意图或绕过授权   |
| [AgentGo CLI 设计](./agentgo-cli-design_zh.md)     | 为开发与运维提供可脚本化的管理入口          | 替代图形客户端的会话体验 |

模块协作遵循“客户端发起、资源按权授权、SA 编排、Runtime 执行、结果可追溯”的边界。任何跨模块调用都应携带可审计的身份、会话或任务关联信息，并通过后端发布的契约完成。
