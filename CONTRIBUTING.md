# Contributing to AgentGo Docs

## Before you start

Read `AGENTS.md` for project rules and `SECURITY.md` for vulnerability reporting. Keep changes focused and preserve unrelated work.

## Issue-first workflow

All bugs, documentation work, improvements, and new requirements must begin with a GitHub Issue. Include the problem or goal, context, acceptance criteria, and any screenshots or reproduction details. Use the issue's number in the implementation branch and pull request.

## Branches and pull requests

Use the following flow:

```text
main -> release/<name> -> feature/<name> or fix/<name> -> PR -> release/<name> -> PR -> main
```

`main` and `release/*` are protected and must not receive direct pushes. The `deploy` branch is generated by GitHub Actions after a PR reaches `main`.

Every PR must explain the user impact, include validation steps, and pass all required checks. UI changes should include a screenshot or a concise visual description.

Every PR must link an issue with a closing reference such as `Closes #123`. Direct pushes to `main` and `release/*` are blocked. Release branches are retained; merged `feature/*` and `fix/*` branches are removed automatically.

## GitHub Projects

Use a project board as the cross-issue view of work:

1. Create one project for the repository and add repository Issues and Pull Requests as items.
2. Use a simple status flow: `Backlog`, `Ready`, `In progress`, `In review`, `Done`.
3. Add views for the board, a table grouped by priority, and a roadmap grouped by milestone.
4. Set issue templates and labels before triage. Keep the issue as the source of truth; the project tracks status and planning metadata.
5. Use automation to move newly added issues to `Backlog`, move opened PRs to `In review`, and archive or mark merged work as `Done`.
6. Add milestones for releases and use the `release/*` branch name consistently with the milestone name.

## Commits

Use `<emoji>[<type>]: <message>`:

```text
✨[feat]: add bilingual sidebar navigation
🛠️[fix]: preserve theme preference on reload
📝[docs]: clarify extension guide
```

Each commit must contain no more than 200 changed lines total. Split work into reviewable commits when necessary.

## Local validation

```bash
pnpm typecheck
pnpm test
pnpm lint
pnpm format
pnpm build
```

Do not commit `node_modules`, `dist`, coverage output, secrets, or generated local files.
