# AgentGo CLI 设计

AgentGo CLI 为开发者、管理员和自动化流程提供 AgentGo 的命令行入口。它面向资源、Agent、任务和运行状态的管理与查询，复用与客户端一致的已发布服务端契约，而不实现另一套业务规则。

## 命令组织

命令按领域分组，并保持稳定、可发现的动词和资源名。建议采用以下形态；实际命令及参数以正式发布的 CLI 参考文档为准。

```text
agentgo auth <subcommand>
agentgo resource <list|get|create|update|delete>
agentgo agent <list|get|create|update|delete>
agentgo task <submit|get|cancel|logs>
agentgo config <get|set>
```

读取操作默认无副作用；创建、更新、删除、提交和取消必须清楚展示目标和结果。可能造成广泛影响的操作应支持显式确认、`--dry-run`（适用时）和非交互自动化参数。

## 输入、输出与自动化

| 范围       | 要求                                                                                 |
| ---------- | ------------------------------------------------------------------------------------ |
| 输入       | 支持参数、标准输入和安全的配置引用；秘密不应出现在命令行参数、历史记录或普通输出中。 |
| 输出       | 面向人类时提供简洁摘要；面向自动化时提供稳定的机器可读格式，并将诊断写入标准错误。   |
| 退出状态   | 成功、用户输入错误、认证/授权拒绝、远端失败和本地配置错误应可被脚本区分。            |
| 分页与筛选 | 使用服务端定义的分页、排序和筛选语义，不在本地伪造不同的行为。                       |

## 认证与配置

CLI 使用平台支持的安全凭据存储或短期会话，不将访问令牌写入项目文件、命令历史或调试日志。配置具有明确的作用域和优先级，且允许用户查看配置来源但不显示敏感值。非交互运行应能明确禁用提示，并在缺少必要身份或确认时以可脚本处理的错误退出。

## 可观测性和兼容性

每个命令可输出关联请求或 Execution 标识，便于用户转向 Web/桌面端查看详情。CLI 对破坏性变更遵循版本化与弃用策略；新增本地快捷方式不能改变后端授权、审计和任务编排规则。
