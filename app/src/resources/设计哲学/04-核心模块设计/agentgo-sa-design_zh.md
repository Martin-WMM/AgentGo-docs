# AgentGo SA 设计

AgentGo SA 是一次 Agent 任务的编排边界。它将输入、已授权上下文和 Agent 配置组织为可追踪的 Execution，并协调模型推理、确认、工具执行和最终响应。SA 不直接拥有资源或执行外部工具，而是调用资源管理模块与 Agent Runtime。

## 节点职责

| 节点            | 输入                                      | 输出与约束                                                           |
| --------------- | ----------------------------------------- | -------------------------------------------------------------------- |
| Input Node      | 用户输入、Context、Agent Config、标识信息 | 创建隔离的任务状态，规范化内容并关联 Session、Task 与 Execution。    |
| Compliance Node | 规范化请求和可运行配置                    | 在模型与工具使用前实施策略、权限和内容校验；不通过即终止或要求澄清。 |
| LLM Node        | 合规后的上下文和工具结果                  | 生成回复或受约束的行动意图；不得把模型输出视为已获准执行。           |
| Execution Node  | 行动意图                                  | 校验工具、参数、授权和确认状态，再向 Runtime 派发受控请求。          |
| Response Node   | 最终模型输出或终止状态                    | 生成面向用户的响应并隐藏内部敏感细节。                               |

## 执行闭环

```text
Input → Compliance → LLM ──无行动──→ Response
                       │
                       └─行动→ Execution → Agent Runtime → Tool Message ─┘
```

每一个循环都必须受 Execution 的时间、预算、步骤和取消边界约束。工具结果应结构化地记录成功、失败、可安全展示的摘要及关联引用，再返回 LLM Node；原始敏感值不进入模型上下文或用户响应。

## 幂等、恢复与审计

SA 为每次提交维持稳定关联标识，并对外部副作用使用幂等语义或显式确认。服务中断后，恢复以已持久化的状态和已完成步骤为依据，绝不盲目重放可能造成副作用的调用。审计记录必须能回答：谁发起、哪个 Agent 在何种资源授权下做了何项动作、结果为何以及何时终止。
