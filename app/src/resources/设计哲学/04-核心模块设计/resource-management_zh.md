# 资源管理模块设计

资源管理模块是 AgentGo User Environment 的权威入口。它管理文件工作区、数据源、Web SaaS、凭据、用户资料、记忆、MCP Server、Skill 和 Agent 定义，使这些资源可被安全发现并在需要时装配到任务上下文中。

## 核心职责

| 职责         | 设计要求                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------- |
| 生命周期管理 | 为资源提供创建、版本更新、停用和删除流程，并保留必要的归属与审计信息。                   |
| 访问控制     | 按 User、Organization、Role、Permission 和资源可见性评估访问；运行时每次加载都重新校验。 |
| 凭据隔离     | 凭据与业务资源分离存储；调用方只能获得受控使用权，不能获得明文。                         |
| 能力发现     | 向已授权的 Agent Runtime 提供资源元数据和可运行配置，而非无差别暴露所有资源。            |
| 可追溯性     | 记录资源变更、授权变更、发现、加载和使用结果，关联 Actor、Task 或 Execution。            |

## 运行时装配

资源不等于上下文。任务开始时，资源管理模块根据身份、任务目标、Agent 配置、资源状态和授权范围筛选候选资源；Context Manager 再将必要信息转换为 Runnable Configuration。该过程遵循最小披露：只装配完成任务所需的描述、能力与受控引用。

```text
资源定义与授权 → 候选资源筛选 → 权限复核 → 可运行配置 → AgentGo SA
                                                        ↓
                                               Agent Runtime 受控调用
```

## 一致性与失败处理

资源变更必须具有明确版本或更新时间，以便执行可关联到其实际使用的配置。资源被撤销、禁用或凭据失效时，后续加载和调用必须失败关闭，并将可恢复的错误返回编排层。删除应遵从发布的保留和审计策略；不得把已删除资源的敏感配置复制到任务上下文或日志中。
