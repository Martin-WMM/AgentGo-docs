# Agent Runtime 设计

Agent Runtime 负责实际执行 Agent 已获批准的外部操作，例如调用 Skill、MCP Server 或其他已授权服务。它是策略已验证的行动意图与真实副作用之间的最后一道执行边界，而不是通用命令执行器。

## 受控执行模型

Runtime 只接收来自 Execution Node 的、带有 Execution 关联信息的请求。每次调用都解析为目标能力、允许的参数范围、资源引用、凭据引用、超时和结果处理策略；这些信息共同构成受控调用，而不是可自由拼接的命令。

| 阶段   | Runtime 行为                                                        |
| ------ | ------------------------------------------------------------------- |
| 准入   | 验证调用者、Execution 状态、工具可用性、资源授权与确认要求。        |
| 适配   | 将标准化请求映射到 Skill、MCP 或服务特定协议，并进行参数校验。      |
| 执行   | 应用超时、并发、重试和取消控制；最小化凭据的作用域与存活时间。      |
| 归一化 | 将输出转换为结构化 Tool Message，区分结果、错误、引用和可展示摘要。 |
| 记录   | 生成与 Execution 关联的审计与运行指标，不写入秘密明文。             |

## 安全边界

工具注册表必须采用允许列表，并声明输入输出约定、所需权限和副作用等级。Runtime 不接受由模型直接指定的任意端点、任意本地命令或凭据值；对写入、删除、发布和外部通知等动作，应要求 SA 已验证的确认状态。调用失败默认不扩权、不自动切换到更高权限的资源。

## 结果与可靠性

Runtime 返回可由 SA 安全处理的结果，而非仅返回未处理的供应商响应。网络或依赖故障应包含可分类的失败原因和重试建议；重试只适用于明确无副作用或具有幂等保证的操作。取消请求需尽力传递给下游，并在最终状态中准确反映是否已产生副作用。
